# Finora 0.3.0 Release Preparation Plan

Target version: **0.3.0**  
Target application build: **3**  
Database schema target: **2 (unchanged unless a persisted-model change is deliberately approved)**  
Preparation opened: **2026-08-24**

Finora 0.3.0 is the proposed next semantic-minor release after the current 0.2.0 (build 2) source line. The target is justified by additive platform capability and release/tooling improvements rather than a breaking finance-data contract.

This document is a preparation contract, not a statement that 0.3.0 has already shipped. Version metadata should be advanced only when the exact release-candidate source is ready to enter final packaging/native/browser validation.

## Release objectives

1. Merge the universal cross-platform foundation without regressing the established .NET MAUI application.
2. Preserve the local-first finance model and integer-minor-unit correctness rules.
3. Keep Android, iOS/iPadOS, Mac Catalyst, and Windows MAUI builds fully validated.
4. Add a validated Avalonia desktop foundation for Linux, Windows, and macOS.
5. Add a validated WebAssembly/PWA presentation foundation while keeping browser finance persistence disabled until its security/durability contract is actually implemented and tested.
6. Keep ChromeOS support represented through Android and/or Web/PWA delivery paths rather than claiming a separate native ChromeOS runtime.
7. Validate the Microsoft.Maui.Controls 10.0.100 servicing update across the existing strict build/test matrix.
8. Remove temporary/generated repository debris and keep tracked-file documentation coverage exact.
9. Keep release claims tied to exact commit/run evidence.

## Proposed 0.3.0 scope

### Platform foundation

- `Finora.Universal` shared Avalonia presentation/runtime boundary.
- `Finora.Universal.Desktop` native desktop host for Linux, Windows, and macOS.
- `Finora.Universal.Browser` WebAssembly/PWA host.
- `Finora.CrossPlatform.slnx` as the cross-platform solution entry point.
- Cross-platform structural checker and GitHub Actions matrix.
- Linux, Web/PWA, ChromeOS, and platform-matrix documentation.

### Existing application compatibility

The established MAUI product path remains authoritative for:

- Android;
- iOS/iPadOS;
- Mac Catalyst;
- Windows.

The universal host must not silently replace MAUI platform integrations that are not yet feature-equivalent.

### Dependency baseline

The 0.3.0 candidate should validate at least the following currently selected package lines:

- Microsoft.Maui.Controls 10.0.100;
- Microsoft.EntityFrameworkCore 10.0.10;
- Microsoft.EntityFrameworkCore.Sqlite 10.0.10;
- SQLitePCLRaw.bundle_e_sqlite3 3.0.5;
- Avalonia family 12.1.1;
- Microsoft.NET.Test.Sdk 18.9.0;
- xUnit 2.9.3;
- xunit.runner.visualstudio 4.0.0.

Any later dependency refresh must receive the same restore/build/test/security review and must not be added merely to increase version numbers.

## Native/browser evidence required before platform release claims

Automated source builds are necessary but not sufficient. Distribution claims require platform-specific validation for the exact package/runtime being shipped.

### MAUI platforms

- signed Android AAB/APK install/launch/upgrade validation;
- Windows package/signing/install/upgrade validation;
- Apple signing/provisioning/archive/distribution validation;
- biometrics/Windows Hello, notifications, file pickers/sharing, privacy/capture behavior, localization, accessibility, interrupted restore, low-disk behavior, and installed schema migration where applicable.

### Linux

- package/runtime launch on representative distributions;
- X11 baseline validation;
- native Wayland only if separately enabled and validated;
- filesystem location/permissions;
- keyboard/focus/accessibility behavior;
- backup/import/export/file-picker behavior once the corresponding universal UI features reach parity.

### Web/PWA

- optimized publish output served over HTTP(S);
- browser launch and responsive UI checks;
- PWA manifest/installability checks;
- cache/offline-shell behavior only when actually implemented;
- no claim of durable finance persistence while browser storage remains disabled;
- browser-local encrypted persistence requires explicit design, quota/eviction handling, migration, integrity, backup/restore, recovery, privacy, and offline testing before it can enter the release scope.

### ChromeOS

- Android path validation on supported ChromeOS devices where used;
- Web/PWA path validation in ChromeOS browser where used;
- no dedicated-native ChromeOS claim without an actual supported implementation.

## Release exclusions unless separately completed

The following are not implied by the 0.3.0 platform foundation:

- complete MAUI-to-Avalonia screen-by-screen parity;
- browser finance persistence;
- cloud synchronization or Finora accounts;
- server-backed entitlement;
- automatic exchange-rate conversion;
- default analytics/advertising telemetry;
- native Wayland release support;
- store approval or production signing merely because source builds pass.

## Merge and dependency housekeeping

Before closing the 0.3.0 preparation cycle:

- the cross-platform PR should be green and mergeable;
- any superseded Dependabot PR should be closed with a clear superseded reason after the equivalent update is validated in the merged candidate;
- open issues should be reviewed for release relevance;
- host-level `main` protection issue #28 remains a governance action until GitHub reports an active protection/ruleset configuration;
- generated/temp files must not remain tracked;
- documentation coverage and local Markdown links must stay valid.

## Completion definition

The repository may describe **0.3.0 as prepared for release-candidate packaging** only after the exact source candidate has passed the automated evidence above and the version metadata has been updated consistently.

The repository may describe a specific platform as **released/production-ready** only after its required native/browser packaging, installation, runtime, privacy, accessibility, recovery, and policy evidence has actually been performed for that candidate.
